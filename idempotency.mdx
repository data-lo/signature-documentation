---
title: "Idempotencia"
description: "Reintenta la creación de un documento sin duplicarlo ni cobrarlo dos veces."
---

Si la conexión se corta, no sabes si el documento se creó. Por eso `POST /api/v1/integration/documents` exige el header `Idempotency-Key`: repetir la petición con la misma clave devuelve el documento original en lugar de crear otro.

```bash
curl -X POST "$FIRMALO_API_URL/api/v1/integration/documents" \
  -H "X-API-Key: $FIRMALO_API_KEY" \
  -H "Idempotency-Key: erp-contrato-2026-000184" \
  -F "file=@contrato.pdf;type=application/pdf" \
  -F "payload=<$PAYLOAD_FILE"
```

Los demás endpoints no la usan.

## Elige la clave

- Usa un valor único por documento, como su folio en tu sistema.
- Debe tener de 1 a 255 caracteres ASCII visibles.
- Cada API key tiene sus propias claves: dos llaves pueden usar el mismo valor sin chocar.
- Guarda la clave junto al documento antes de la primera llamada, para reenviar la misma en cada reintento.

## Qué pasa al repetir una petición

La API compara la clave, el PDF y el texto exacto de `payload`.

| Situación | Respuesta |
| --- | --- |
| Clave nueva | `201` con el documento creado. |
| Misma clave y mismo contenido, ya completada | `200` con el documento original y `Idempotent-Replayed: true`. No se crea, cobra ni notifica nada. |
| Misma clave y mismo contenido, aún en curso | `409 INTEGRATION_IDEMPOTENCY_KEY_IN_PROGRESS`. Espera unos segundos y repite. |
| Misma clave con otro PDF u otro `payload` | `409 INTEGRATION_IDEMPOTENCY_KEY_MISMATCH`. Usa una clave nueva. |
| Sin `Idempotency-Key` | `400 INTEGRATION_IDEMPOTENCY_KEY_REQUIRED`. |

<Warning>
  `payload` se compara como texto. Si al reintentar lo vuelves a serializar con otro orden de campos u otros espacios, cuenta como otro contenido y recibes `INTEGRATION_IDEMPOTENCY_KEY_MISMATCH`. Guarda el texto que enviaste y reenvía ese.
</Warning>

## Cuánto dura una clave

- Una clave completada dura **24 horas**. En ese plazo, cualquier reintento devuelve el documento original.
- Después, la clave se libera y una petición con ella crea un documento nuevo.
- Si la creación falla, por ejemplo por falta de créditos o un error de validación, la clave se libera de inmediato: corrige la causa y reintenta con la misma clave.

## Cómo reintentar

<Steps>
  <Step title="Reintenta los fallos de red y los 5xx">
    Repite la misma petición, con la misma clave y el mismo contenido, esperando cada vez más entre intentos.
  </Step>
  <Step title="Espera si la petición sigue en curso">
    `INTEGRATION_IDEMPOTENCY_KEY_IN_PROGRESS` significa que la primera petición todavía se procesa. Espera y repite.
  </Step>
  <Step title="Corrige antes de repetir un 4xx">
    Un `400`, `402` o `422` no se resuelve repitiendo. Corrige la petición o recarga créditos; después puedes usar la misma clave.
  </Step>
</Steps>
